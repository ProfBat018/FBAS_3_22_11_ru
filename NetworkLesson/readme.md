## Типы сетей в Docker

Всего в Docker есть 3 типа сетей. 
1. None
2. Host
3. Bridge

### None

Этот тип сети означает, что контейнер не будет иметь сетевого интерфейса. То есть по факту контейнер не будет иметь доступа к сети. Нет ни внешнего, ни внутреннего доступа. Такой драйвер сети используется, когда контейнеру не нужно взаимодействовать с другими контейнерами или с внешним миром. К примеру это может быть программа для расчетов или для обработки данных.

### Host

В данном случае контейнеры запукаются напрямую у вас на машине. По факту физически они находятся в одной сети с вашим хостом. То есть они имеют доступ к тем же ресурсам, что и ваш хост, но работают при этом в Docker контейнере. Такой способ имеет свои плюсы и минусы. Тут не получится связать ваш порт и порт докера. Как минимум потому что он не в сети докера и вам это не надо. С точки зрения безопасности это не самый лучший вариант, так как контейнеры могут получить доступ к ресурсам вашего хоста.


### Bridge
Это способ по умолчанию. Контейнеры запускаются в своей сети, которая изолирована от вашей. По умолчанию контейнеры могут общаться между собой, но не могут общаться с внешним миром. Для того чтобы контейнер мог общаться с внешним миром, нужно пробросить порт. Это можно сделать с помощью команды -p.


На прошлом уроке, когда мы проходили `docker compose` мы создавали сеть. Это была сеть типа bridge. Все сети которые вы создаете сами создаются отдельно от других сетей по умолчанию.

```bash
docker network ls # Показывает все сети
```


```bash
docker network inspect <название сети> # Показывает информацию о сети 
```
